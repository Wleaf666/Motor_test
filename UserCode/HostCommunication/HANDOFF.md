# Motor_test 上位机接入交接

适用对象：实现串口连接、扭矩调试、参数面板和保存按钮的上位机开发者。本文按当前工作区固件接口整理，不包含上位机实现。协议版本为 `0x01`；当前源码发送任务延时为 **10 tick（约 10 ms）**。部署时须确认板上烧录的是对应固件，不能从本文推断旧固件已经升级。

## 1. 必须保留的控制边界

- 上电：电压目标和扭矩目标为零、扭矩环关闭、PWM 停止。恢复已保存参数不会自动运行。
- 扭矩采用**绝对值闭环**：上传值和 PID 使用值均为取绝对值后经卡尔曼滤波的幅值；不提供正反方向控制或带符号原始扭矩。
- 扭矩目标默认上限 **3**，可在线调整 `TorqueLimit`。单位沿用传感器标定的工程单位，未确认标定前不要把界面硬写为 N·m。
- 扭矩环是外环：输出 0～18 V 电压目标，再由原电压内环驱动 PWM。目标上限不是 PID 输出电压上限。
- **断开串口不会自动停机**；目标保持最后有效值。关页面、拔线或通信超时不能显示成“已停机”。
- `SetTorqueEnabled(0)` 或 `SetVoltage(0)` 是软件停止：关闭扭矩环、清空 PID 状态、目标电压归零并停止 PWM。不能称为硬件急停。
- `SetTorque(0)` **只把扭矩目标设为零，不关闭扭矩环，也不等价于停止 PWM**。保存前必须显式关闭或发送 0 V，并等待成功应答。
- 扭矩关闭后，选定的扭矩目标仍保留；再次开启会使用这个目标。上位机重新开启前应明确显示并确认目标，不自动恢复运行。

## 2. 连接与数据接收

| 项目 | 当前接口 |
| --- | --- |
| 串口 | USART3，115200，8N1，无流控 |
| 接线 | 板端 PC10 TX → 适配器 RX，PC11 RX ← 适配器 TX；共地，3.3 V TTL |
| 帧长 | 双向固定 14 字节，不是文本，无换行和帧尾 |
| 数值 | 多字节字段均小端；浮点为 IEEE 754 float32 |
| 应答 | `0x82`，回显请求序号与操作码 |
| 测量反馈 | `0x81`，独立反馈序号 |

板子不要求上电时连接电脑；后接串口可以接收后续反馈。校准、无载归零结束前没有正常业务通信；以收到有效帧为依据，不用固定倒计时自动开启输出。

上位机必须使用流式缓冲解析：串口一次读取可能是半帧、多帧或任意片段。搜索 `A5`，不足 14 字节则继续收；版本、类型或 CRC 不正确时从候选帧头后一个字节继续搜索；完整合法帧消费 14 字节。接收器必须同时接受 `81` 和 `82`，不能仍只识别旧反馈类型。

### 帧公共字段

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 1 | 帧头 `A5` |
| 1 | 1 | 版本 `01` |
| 2 | 1 | 操作码 / 上行类型 |
| 3 | 1 | 请求序号或反馈序号，0～255 回绕 |
| 4～7 | 4 | word0 |
| 8～11 | 4 | word1 |
| 12～13 | 2 | CRC16，低字节在前 |

CRC：**CRC-16/CCITT-FALSE**，多项式 `0x1021`，初值 `0xFFFF`，输入/输出不反射，最终异或 `0x0000`，只覆盖前 12 字节。`123456789` 的 CRC 为 `0x29B1`；不是 MODBUS。

## 3. 下行命令与应答数值

每个请求使用一个序号。表中的应答数值位于 `0x82` 帧的 word1；是否成功必须先检查 Result，不能仅看数值。

| 操作码 | 名称 | word0 | word1 | 成功应答数值 |
| --- | --- | --- | --- | --- |
| `01` | SetVoltage | float 电压 V | 全零 | 已应用电压目标 |
| `02` | SetTorque | float 扭矩幅值目标 | 全零 | 已接受扭矩目标 |
| `03` | SetTorqueEnabled | uint32：0 关闭，1 开启 | 全零 | 0 / 1 |
| `10` | SetParameter | uint32 参数 ID | float 新值 | 已应用参数值 |
| `11` | GetParameter | uint32 参数 ID | 全零 | 当前 RAM 参数值 |
| `12` | SaveParameters | 全零 | 全零 | 存储状态码，成功为 0 |
| `13` | GetState | 全零 | 全零 | 当前选定扭矩目标 |

- 电压必须有限且位于 `[0,18]`。非法电压在接收层直接丢弃，**没有应答**。
- 扭矩目标必须有限且位于 `[0,TorqueLimit]`；负值不会被自动取绝对值，返回 `InvalidValue`。绝对值处理针对传感器反馈。
- 设置扭矩目标不会自动使能；即使当前为手动电压模式，也只是预选扭矩目标，不接管输出。
- 开启需要 `feedback_valid=1`。成功意味着控制模式已开启，**不代表实测扭矩已到目标**；下一次 TIM3 计算后才更新外环输出。
- 重复发送开启命令会停止再启动 PWM 并复位 PID，不是无副作用的“保持在线”。按钮状态查询应使用 `GetState`，不能周期重发开启。
- 扭矩开启时，非零电压命令返回 `ModeConflict`；0 V 在任意模式下都执行软件停止。手动电压调试应先关闭扭矩环。
- 每次成功 `SetParameter` 都会复位扭矩 PID，即使数值相同；修改 Q/R 还会让滤波器在下个有效样本重新初始化。不要持续重发未变化的参数。
- 未知操作码、未知参数 ID、非零保留字段、CRC 或版本错误，以及接收 FIFO 满时的新命令均静默丢弃，无应答。

## 4. 参数面板

| ID | 参数 | 无有效保存记录时的默认值 | 固件数值要求 | 界面含义 |
| --- | --- | --- | --- | --- |
| 1 | Kp | 1 | 有限且 ≥0 | 扭矩 PID 比例增益 |
| 2 | Ki | 0 | 有限且 ≥0 | 扭矩 PID 离散积分增益 |
| 3 | Kd | 0 | 有限且 ≥0 | 扭矩 PID 离散微分增益 |
| 4 | Q / ProcessNoise | 0.01 | 有限且 ≥0 | 每个新扭矩样本的过程方差 |
| 5 | R / MeasurementNoise | 0.01 | 有限且 >0 | 测量方差 |
| 6 | TorqueLimit | 3 | 有限且 >0 | 允许的目标扭矩幅值上限 |

所有界面输入先校验，再编码为 float32；以应答返回的 float32 值刷新已应用值，避免显示成比下位机精度更高的“已生效参数”。重连后逐项 `GetParameter`，不能用默认值覆盖设备当前配置。

### PID 和滤波含义

- 扭矩 PID 在 **TIM3 100 Hz** 回调执行，直接使用库 `PIDMotor`。积分为 `Ki×误差` 的逐次累计，微分为 `Kd×本次与上次误差之差`；上位机不能再乘除 `dt`。不是另一套连续时间 PID 参数接口。
- 电压内环为 TIM2 10 kHz。串口发送周期改变不改变这两个控制周期。
- 卡尔曼来自 `Math::EKF` 的一维模型；Q/R 单位均为扭矩工程单位的平方。提高 Q 倾向跟随新数据，提高 R 倾向平滑；**不要显示为截止频率 Hz**。
- 卡尔曼只在新的 ADS1220 有效样本到来时更新。当前 Normal20 配置下驱动读取间隔至少约 57 ms；100 Hz 上报不等于 100 Hz 新扭矩测量。
- 滤波无法证明机械振荡已消失。默认增益和 Q/R 是调试起点，不是已实板整定参数。
- 提高 TorqueLimit 不自动提高当前目标；降低到当前目标以下会立即钳位选定目标。设置后 `GetState` 刷新目标栏。固件没有额外的机械额定上限校验，不能把“接受新上限”解释为安全认证。

## 5. 上行解析

### `81`：测量反馈

word0 是实测电压 V，word1 是滤波后的非负扭矩幅值。两者不是目标值，也不保证同一采样时刻。

当前发送任务每轮延时约 10 ms：无待发应答时约 100 帧/秒；应答优先、DMA 忙或 Flash 操作会使反馈让位、跳帧或暂停，不能要求严格 10 ms。反馈序号仅在反馈成功提交发送后递增，与请求序号独立；序号跳变不等价于 ADC 丢样。

反馈帧没有有效性、时间戳、故障原因或数据龄期。传感器出错时可能继续上传旧测量值；不能用“收到 81”认定传感器健康。UI 分别显示“串口收到数据”和最近一次应答中的反馈状态。

### `82`：请求执行结果

字节 3 回显请求序号；word0 按 uint32 小端读取：

| 位 | 含义 |
| --- | --- |
| 0～7 | Result |
| 8 | torque_enabled：执行结束时扭矩环是否开启 |
| 9 | feedback_valid：最近有效反馈状态，不带龄期 |
| 16～23 | 原请求操作码 |
| 其他 | 当前为零 |

word1 按 float32 读取，具体意义见命令表。匹配应答须同时检查**请求序号和原操作码**；参数 ID 不回显，单请求在途时从请求上下文关联。GetState 的数值不是电压目标，`torque_enabled=0` 也不代表手动电压输出已停止。

| Result | 名称 | 上位机处理 |
| --- | --- | --- |
| 0 | Ok | 更新已应用值/状态；不等价于机械动作完成 |
| 1 | InvalidValue | 保留原有效值，提示检查有限数、范围及启停值 |
| 2 | NotReady | 尚无有效扭矩反馈；保持按钮关闭，不自动重试开启 |
| 3 | ModeConflict | 扭矩模式禁止非零手动电压；先显式关闭 |
| 4 | OutputActive | 保存被拒绝，先停止输出并等待成功应答 |
| 5 | StorageError | 显示存储状态，不标记已保存，不自动重新启动 |
| 6 | HardwareError | 显示启停失败；不得显示已停机/已启动，不自动恢复输出 |

通常失败时数值为零，不回显 NaN/Inf。`SaveParameters` 实际调用存储层后，数值为如下存储状态；运行前置检查失败只返回 Result=4、数值=0：

| 存储码 | 名称 |
| --- | --- |
| 0 | Ok |
| 1 | NotFound |
| 2 | InvalidLayout |
| 3 | InvalidParameters |
| 4 | OutputActive |
| 5 | UnlockFailed |
| 6 | EraseFailed |
| 7 | ProgramFailed |
| 8 | VerifyFailed |
| 9 | LockFailed |

## 6. 按钮与操作流程

| 控件 | 下位机调用/界面要求 |
| --- | --- |
| 连接 | 等有效帧，GetState，再逐项 GetParameter；不自动设置目标或使能 |
| 扭矩目标“下发” | SetTorque，成功后更新已接受目标；不隐式开启 |
| “开启扭矩闭环” | 先下发用户确认的目标，再 SetTorqueEnabled(1)；以成功应答及 bit8 更新按钮 |
| “关闭扭矩闭环” | SetTorqueEnabled(0)，成功后显示关闭；选定目标仍保留 |
| “停止输出” | SetVoltage(0)；等成功应答，不把串口断开当作停止 |
| 电压“下发” | 扭矩模式先关闭；再 SetVoltage，非零电压会启动手动电压控制 |
| 参数“写入/应用” | 逐项 SetParameter，各等应答；仅修改 RAM，不显示已掉电保存 |
| 参数“读取” | 逐项 GetParameter；得到当前生效值，不是独立 Flash 副本 |
| “保存到下位机” | 执行下述停机保存流程；不能只存浏览器 localStorage |

### 停机保存流程

1. 停止自动下发目标/参数，等待之前的请求结束。
2. 发送 `SetTorqueEnabled(0)`（或 `SetVoltage(0)`），必须等 Result=0；失败则终止保存流程。
3. 按用户编辑结果逐项写入六参数中发生变化的项，各等成功应答；需要时逐项读回。参数组没有事务接口，中途失败不能宣称整组已应用。
4. 发送 `SaveParameters`，界面显示“保存中”，暂不发送使能或电压命令。
5. 收到匹配的 Result=0 且存储码=0，才标记“已保存到下位机”；保存不会自动重新启动输出。

写参数不自动擦写 Flash，只有保存命令才写。保存的是当时 RAM 中的全部六项参数，不保存目标、使能或传感器零点。断电重启重新校准、归零并恢复参数，保持零目标和关闭状态。Flash 有写入寿命，不在滑块拖动、定时器或每次输入变化时自动保存；全片擦除或固件下载若擦到参数区，参数仍会丢失。

如果保存应答丢失，**不能通过 GetParameter 证明 Flash 保存成功**，它只读 RAM；协议没有 Flash 状态查询或请求去重。显示“结果未知”，提示人工确认，禁止盲目无限重试。

## 7. 时序、重连和错误恢复

- 固件 FIFO 为 8 条，满时丢弃新请求，非“最后目标覆盖”。上位机使用串行请求队列，最多一条普通请求在途；等待匹配应答后再发送下一条。
- 控制帧保守建议不超过 20 Hz，帧间至少 2 ms，一次 write 提交完整 14 字节。100 Hz 是当前反馈调度，不代表建议上位机以 100 Hz 洪泛命令。
- UI 超时建议值（**上位机策略，不是固件保证**）：普通请求 500 ms，保存 3000 ms；允许按实际串口环境调整。Flash 操作期间反馈间隔可能变长。
- 超时：保持控制状态“未知”，停止自动发送使能/保存，不显示成功。清理超时请求与迟到应答的关联后，使用新序号 GetState 和读参恢复认知；这不能取消已在 FIFO 中的旧请求，也不能证明输出已停。
- 序号只有 8 位，没有会话 ID、去重和重传保护。保留近期超时记录，避免快速复用相同序号/操作码而把迟到应答匹配给新请求。
- 不把连续开启命令当心跳；不要在重连后自动开启。若需停止，明确发送软件停止并检查应答；物理危险时依赖独立硬件断电/急停，不依赖通信恢复。
- 传感器错误可使正在运行的扭矩环关闭；反馈恢复后不会自动重新使能。状态只随应答返回，可用低频 GetState 更新界面，但它不提供完整故障日志。

## 8. 可直接对照的报文

以下每行均包含 CRC，可用于编码器自检；使能/目标报文会改变控制状态，不应在未知硬件状态下自动发送。

| 操作 | 完整十六进制帧 |
| --- | --- |
| 设置扭矩 2.25，序号8 | `A5 01 02 08 00 00 10 40 00 00 00 00 89 6A` |
| 开启，序号9 | `A5 01 03 09 01 00 00 00 00 00 00 00 D0 A2` |
| 关闭，序号10 | `A5 01 03 0A 00 00 00 00 00 00 00 00 47 C8` |
| 设置 R=0.03125，序号11 | `A5 01 10 0B 05 00 00 00 00 00 00 3D 7D A9` |
| 查询 R，序号12 | `A5 01 11 0C 05 00 00 00 00 00 00 00 6D 90` |
| 保存，序号13 | `A5 01 12 0D 00 00 00 00 00 00 00 00 3F 82` |
| 查询状态，序号14 | `A5 01 13 0E 00 00 00 00 00 00 00 00 3E C0` |
| 参数设置成功应答，序号80，环开启且反馈有效，返回0.03125 | `A5 01 82 50 00 03 10 00 00 00 00 3D 71 85` |

最后一帧状态字为 `0x00100300`：Result=0，bit8/bit9=1，原命令=0x10；数值是设置结果，不是参数 ID。

## 9. 接入验收清单

以下是上位机接入者应执行的检查，不代表本次已完成上位机或实板测试：

- 解析分片、粘包、噪声和 CRC 错帧；同时识别 81/82，序号与类型关联正确。
- 打开串口不会启动输出；上电校准中不发送控制，后插串口也能连接。
- 目标、实测值、已应用参数、待保存改动和已保存状态分别显示。
- 未就绪开启失败时按钮不误亮；关闭/停止失败时不误报停机。
- 正负传感器输入对应幅值反馈；单位与真实标定一致。
- 扭矩上限在线增减，降低上限后正确刷新被钳位目标；非法参数不覆盖有效值。
- 写入后未保存的改动不显示为已保存；运行中直接保存被拒绝；停机保存有明确应答。
- 断电恢复六参数但不恢复非零目标/运行状态；不把模拟恢复当作实板掉电验证。
- 拔线、超时、迟到应答、重连时不自动启动、不盲目重试保存；明确独立硬件停止手段。
